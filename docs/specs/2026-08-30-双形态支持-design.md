# 双形态支持（专项 / 全局）设计

## 结论

llm-wiki 模板升级为**单模板双形态**：实例化时可选「专项模式」（clone 后直接 cd 进仓库使用，如 SM 工作台实例的用法）或「全局模式」（现行 `~/.llm-wiki` 发现约定）。模式不落任何配置文件，由文件系统状态推导；四个 Skill 用统一的「工作台根解析」规则同时服务两形态；bootstrap 按模式决定是否建全局链与全局挂载。方案编号 A（被否方案见文末）。

## 背景与需求

- 模板 v0.1.0 只支持全局形态：Skill 路径硬编码 `~/.llm-wiki/`（契约测试 `test_global_skill_paths_absolute` 强制），bootstrap 无条件建发现链、全局挂载并要求接入全局指令路由段。
- 实际存在第二种成熟用法：`llm-wiki-for-work` 实例直接进入仓库使用，Skill 路径全相对（冻结时手工改写）——证明专项形态可行，但模板不支持，只能 fork 后手改。
- 需求：用户实例化时可以选择两种形态之一。
- 现状缺陷（本设计顺带修复）：全局 + 专项并存的机器上，在专项实例目录内命中**全局挂载**的 Skill 时，其硬编码路径会把内容写进全局工作台——写错库。

## 非目标

- 不改动 `llm-wiki-for-work`（冻结的联邦成员，独立演进）。
- 不支持一台机器多个全局实例（`~/.llm-wiki` 唯一）。
- 不提供模式自动迁移脚本；切换步骤文档化，人工执行。
- 不触碰 `wiki/`、`inputs/` 内容目录；wiki schema（`docs/schemas/wiki.md`）无数据结构变更。

## 术语

- **实例**：模板 clone 后经 bootstrap 初始化的仓库。
- **全局实例**：被 `~/.llm-wiki`（Windows：`%USERPROFILE%\.llm-wiki`）指向的实例；一机至多一个。
- **专项实例**：未被发现链指向的实例；使用方式为直接进入仓库目录。
- **工作台根（$WIKI）**：一次 Skill 执行实际操作的实例根目录，按 §5.2 规则解析。

## 设计

### 5.1 模式定义与推导（无配置状态）

「某实例是否全局」唯一判据：`~/.llm-wiki` 是否指向它。不引入 marker 文件或配置项——延续「链接约定而非配置文件」的既有设计哲学（README FAQ），模式状态不可能与文件系统失同步。

### 5.2 工作台根解析规则（Skill 契约核心）

以下段落**逐字**写入四份 SKILL.md 开头（替换现行「工作台在 `~/.llm-wiki`」段），锚句供契约测试匹配：

> **工作台根（$WIKI）**：从当前工作目录向上逐级查找，第一个同时含 `wiki/index.md` 与 `.agents/skills/llm-wiki-ingest/` 的目录即 $WIKI——此时正位于某个 llm-wiki 实例内，专项实例与全局实例同理。未找到时 $WIKI 为 `~/.llm-wiki`（全局发现链，Windows 为 `%USERPROFILE%\.llm-wiki`）；它也不存在则本机未部署工作台，停止并告知用户。下文全部仓内路径以 `$WIKI/` 为前缀。

推导出的行为（规则本身不必写这些，属自然结果）：

- 专项实例内操作 → 写回该专项实例；
- 任意普通项目内操作 → 写回全局实例（现行为不变）；
- 全局实例目录内操作 → 向上查找命中自身，与经 `~/.llm-wiki` 等价；
- 并存机器上、专项实例目录内命中全局挂载 Skill → 解析为该专项实例，**修复写错库缺陷**（专项优先是就近原则的自然结果）。

双条件判定（`wiki/index.md` 且 `.agents/skills/llm-wiki-ingest/` 同时存在）确保普通项目里恰好有 `wiki/` 目录时不会误判。

### 5.3 bootstrap 行为矩阵（bootstrap.sh 与 bootstrap.ps1 同构）

| 动作 | project | global |
|---|---|---|
| `CLAUDE.md → AGENTS.md` 兼容链 | ✓ | ✓ |
| `.claude/.codex` 目录与项目级 Skill 链 | ✓ | ✓ |
| 记忆配置（`settings.local.json` / `config.toml`） | ✓ | ✓ |
| 脚本执行权限、远端指引、Codex 信任指引 | ✓ | ✓ |
| `~/.llm-wiki` 发现链 | ✗ | ✓ |
| 全局 Skill 挂载（`~/.claude/skills`、`~/.codex/skills` 共 8 链） | ✗ | ✓ |
| 打印全局指令路由段 | ✗（改打印专项就绪提示：cd 进本目录即用，无需改动任何全局配置） | ✓ |

模式确定顺序：

1. 显式参数 `--mode global|project`（ps1 为 `-Mode global|project`）优先。要求 global 而 `~/.llm-wiki` 已指向其他实例时，维持现行 `ensure_link` 行为：警告、不覆盖、请人工确认。
2. 无参数时探测：
   - `~/.llm-wiki` 已指向本仓 → global（既有全局实例幂等重跑，兼容旧调用方式）；
   - `~/.llm-wiki` 指向别处 → project，并提示本机全局位已被占用；
   - 不存在：stdin 为 TTY → 交互询问，无默认值、必须明确选择（防误建全局链）；非 TTY → 报错退出并要求显式 `--mode`（自动化场景必须显式决策）。

幂等原则不变：任一模式重复执行安全，脚本只增不减——project 模式重跑不清除既有全局配置。

### 5.4 模式切换

- 专项 → 全局：重跑 `bootstrap --mode global`（仅补建发现链与全局挂载）。
- 全局 → 专项：人工删除 `~/.llm-wiki` 链、`~/.claude/skills/llm-wiki-*` 与 `~/.codex/skills/llm-wiki-*` 链、全局规则中的路由段。步骤写入 README；bootstrap 不做删除操作。

### 5.5 契约测试变更

`tests/test_skill_contracts.py` 中 `test_global_skill_paths_absolute` 替换为 `test_skill_root_resolution`，对四份 SKILL.md 断言：

1. 含锚句 `**工作台根（$WIKI）**：`（根解析段存在）；
2. 无裸相对仓内路径（沿用现行 `BARE_PATH_RE`；`$WIKI/wiki/...` 因前缀 `/` 不命中，天然合规）；
3. 根解析段所在行之外，全文禁止出现 `~/.llm-wiki`（防硬编码回归）；
4. 至少出现一次 `$WIKI/`（确认路径确实走前缀引用）。

`test_skill_frontmatter_and_links`（单一真源）不变。实施按测试纪律执行：先改测试对现行 Skill 跑红，再改 Skill 转绿。bootstrap 属脚本，无既有 shell 测试框架，不新增框架，用 §6 的沙盒验收替代。

### 5.7 兼容与迁移

- 既有全局实例（含本机）：merge template 后重跑 bootstrap（无参数，探测为 global），行为与 v0.1.0 一致。
- 既有非交互自动化：旧实例带发现链，探测规则兼容；仅「全新 clone + 非 TTY + 无参数」由静默建全局链变为报错——这是需要人决策的场景，属修正而非破坏。
- `llm-wiki-for-work`：零改动。其目录内命中全局挂载 Skill 的场景由 §5.2 顺带修复。
- 无目录改名、无 schema 数据迁移。

## 验收标准

1. 契约测试红绿：新 `test_skill_root_resolution` 先对 v0.1.0 Skill 文本失败，Skill 改写后 `python3 -m unittest discover -s tests -v` 与 `python3 scripts/lint-wiki.py` 全绿。
2. 沙盒专项验收：临时 HOME + 临时 clone 执行 `bootstrap.sh --mode project` → `$HOME/.llm-wiki` 不存在、`$HOME/.claude/skills/` 无 `llm-wiki-*`、仓内 `CLAUDE.md` 与项目级 Skill 链齐全；重跑幂等。
3. 沙盒全局验收：`--mode global` → 发现链、8 条全局挂载齐全，输出含路由段；重跑幂等。
4. 探测验收：沙盒内已有发现链时无参数重跑走 global；全新实例非 TTY 无参数退出码非 0。
5. 本机实例：main 合入后重跑 bootstrap，输出全部「已就位」，现有测试与 lint 保持绿。
6. `bootstrap.ps1` 与 sh 逐段同构（代码评审比对）；Windows 真机验收本次无环境，CHANGELOG 标「待验收」。

## 被否方案

- **B（bootstrap 按模式渲染 Skill 占位符）**：Skill 正本变生成物——改写入库骨架文件则模板升级 merge 必冲突，破坏「升级只动骨架、冲突面接近零」的核心承诺；渲染产物不入库则单一真源契约与测试须整体重构。代价大于收益。
- **C（模板保持全局专用，专项走 fork 指引）**：不满足「用户可选择」的需求本身。
