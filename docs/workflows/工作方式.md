# 工作方式

本工作台从一套跑了几个月的实际工作仓库抽出，再按 LLM Wiki 把 wiki 提升成编译核，并做了全局化。具体业务可以换，下面六条不要换。

## 1. 原料与成稿分离

```
inputs/manual/     人在对话里说的、截图里的、丢了就没的事实。
inputs/raw/        域扩展采集来的原始数据（按需建）。只追加，不改写。
inputs/common/     长期人工基准（按需建）：范围、名册、职责。可重采的直接改这里。
config/registry.md 个人项目仓库、域扩展与外部文档路径的唯一登记处。
outputs/           生成结果。随时可以扔掉重来。
wiki/              编译知识。提问先读这里，不要从 raw 重推。
```

禁止改 `raw/` 不是洁癖，是为了让再生成成为可能：原料稳定，成稿才是函数。修正事实走 `manual/`。

## 2. 分层写入

全局化后写入前先判层（`docs/schemas/分区与共享.md`）：项目私有留项目；单项目跨会话进 `wiki/projects/<项目>/`；跨项目复用进公共层；涉他敏感进 `wiki/private/`。同一事实不两写。

## 3. 采集属于域扩展

内核不含采集器。一个数据源一条采集途径，属于某个域扩展：脚本只把原始数据落到该域的 `inputs/raw/<来源>/`，写 `metadata.json`，维护自己的水位线（`state/collectors/`，失败不推进）；不做筛选、不写结论。快照落 `<采集日>/`，切片落 `<周期>/`，两种时间语义不要混。细则见 `docs/workflows/新业务域落地.md`。

## 4. 知识要编译，记忆只记偏好

| 层 | 位置 | 记什么 |
|---|---|---|
| 记忆 | `.memory/` | 换会话仍有用、且代码和 git 里读不出来的偏好、纪律、外部指针 |
| wiki | `wiki/` | 领域对象、机制、案例、学习。给下次提问用 |
| 成稿 | `outputs/` | 给别人看的产物。可再生成 |

写入门：任务收口形成跨会话价值默认 ingest，用户说「不用」才跳过。不要每轮问「要不要记」。

## 5. 收口即上传

ingest 收口跑 `scripts/sync.sh`：pull --rebase → commit → push。rebase 冲突停下交人工，禁止 force；无远端仍本地提交——缺 remote 不是跳过提交的理由。

## 6. 模板不碰内容

骨架（schemas、skills、scripts、tests、根说明）由模板演进，`wiki/`、`inputs/` 内容归个人；升级 = merge 模板上游。两边职责不混，升级永远低冲突。

## 派生纪律

- 阶段状态不得升级。「讨论中」不能写成「已交付」。缺数字写「待补证据」。
- 文风管交付物，不只是对话。先结论后依据。
- 凭证不进仓库、不进对话存盘。
- 回复末尾要收口。
