# 新业务域落地（三件套）

不要先画一张完美的目录树。要用到一个域时，按下面三步做。

## ① 采集

一个数据源一条途径。产出是落盘，不是结论。

```
scripts/collect-<来源>.sh
    → inputs/raw/<来源>/<采集日或周期>/
        metadata.json     必有：collected_at、是否完整、失败列表
        index.json        可选：条目清单、stop_reason
        <原始文件>        保持原样
```

在 `config/registry.md` 的「域扩展」表登一行（含敏感级别）。不要把 URL、账号写进口径文档。

脚本只采集不判断；失败不推进水位线；重复执行幂等；不读凭据文件。

## ② 口径

新建 `docs/domains/<域>.md`，并在 `AGENTS.md` 的「业务域路由」加一行。没有这一行，Agent 下次不会主动读这份口径。

## ③ 产出（按需）

只有「每次都要长得一样」时才在域扩展仓内建 `templates/<域>模板.md`；呈现层样式由域扩展自带，内核不含模板。

```bash
./scripts/new-domain.sh <英文短名>
```

脚本只写 `docs/domains/<域>.md`，不预建空的 `inputs/raw/` 或 wiki 页。有采集脚本再 mkdir raw 并在 `config/registry.md` 登记；有稳定结论再建 `wiki/projects/<名>/`。
